# 6. Functional requirements

**Статус:** Draft

| ID | Требование | Приоритет | Проверка |
|---|---|---|---|
| FR-001 | Система должна позволять пользователю начать вход, указав email. | Must | Интеграционный тест API |
| FR-002 | Система должна подтверждать владение email до выдачи авторизованной сессии. | Must | Тест без подтверждения / с валидным подтверждением |
| FR-003 | При первом успешном подтверждении email система должна создавать учётную запись, если она отсутствует. | Must | Тест первого входа |
| FR-004 | Авторизованный пользователь должен получать список доступных ему VPN-серверов. | Must | API-тест доступа |
| FR-005 | Приложение должно позволять выбрать сервер из доступного списка. | Must | UI-тест |
| FR-006 | Приложение должно позволять инициировать подключение к выбранному серверу. | Must | Тест на целевом устройстве |
| FR-007 | Приложение должно показывать состояние подключения, полученное от native-компонента. | Must | Интеграционный тест состояний |
| FR-008 | Приложение должно позволять отключить активный VPN-туннель. | Must | Тест на целевом устройстве |
| FR-009 | Приложение должно показывать профиль и статус подписки пользователя. | Must | API/UI-тест |
| FR-010 | Система должна обрабатывать сбои сети и предоставлять пользователю возможность повторить безопасный запрос. | Must | Тест сетевых ошибок |
| FR-011 | Система должна показывать тариф и условия до подтверждения покупки. | Should | UI-тест |
| FR-012 | Backend должен проверять платёжное подтверждение перед активацией подписки. | Must, если платежи в MVP | Интеграционный тест |
| FR-013 | Основные разделы должны быть доступны без использования жестов. | Should | Проверка доступности навигации |
